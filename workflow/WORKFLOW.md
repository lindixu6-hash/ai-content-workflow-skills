# Content OS End-to-End Workflow

## 主管线

```text
播种（输入）
  ↓ HUMAN GATE 01
发芽
  ↓ HUMAN GATE 02
成长（给初稿）
  ↓ HUMAN GATE 03
修剪（dbs-content）
```

四个节点之外，不新增标题确认、编导确认、真实经历页或五维审核页。

## 状态与产物

| 状态 | 必要输入 | 产物 | 完成条件 |
|---|---|---|---|
| 播种 | 原始选题、平台 | 人群、变化、冲突 | 用户确认 |
| 发芽 | 已确认种子 | 四张机制不同的芽 | 用户选择至少一张 |
| 成长 | 所选芽、真实经历、证据 | 完整初稿 V1 | 用户读完并确认 |
| 修剪 | 最新初稿 V1 | DBS 内容创作诊断 | 用户选择是否采用 |

## 1. 播种（输入）

```text
使用 content-os-pipeline。
播种：找不到真正热爱的事情，就去看手机相册。
平台：小红书。
```

本阶段只确认：

- 原始选题。
- 目标人群。
- 看完后的状态变化。
- 核心冲突。

用户说“发芽”后才进入下一阶段。

## 2. 发芽

```text
发芽。
```

系统输出四张芽，每张包含：

- 一个可核验的跨领域事实。
- 与当前选题共享的因果机制。
- 一句能直接服务正文的 Aha。

用户选择芽后才允许成长。系统不能替用户选择。

## 3. 成长（给初稿）

```text
选择第 2 张芽，成长。
我的真实经历是：……
```

成长内部顺序：

```text
补足真实经历与证据
  ↓
平台编导（小红书时调用 xiaohongshu-viral-director）
  ↓
完整初稿 V1
```

这三步属于一个用户可见节点，不拆页、不要求额外确认。

初稿必须包含：

- 标题。
- 完整正文。
- 可拍摄证据。
- 可截图证据。
- 待核验项。

初稿展示后停止。用户说“修剪”才进入下一阶段。

## 4. 修剪

```text
修剪。重点检查开头和 AI 味。
```

总控将选题、平台和最新初稿交给外部 `dbs-content`。

DBS 负责：

1. 内容形式与平台匹配。
2. 文字洁癖。
3. 封面与标题。
4. 表达效率。
5. 认知落差。
6. AI 辅助方式。
7. 一条可以立即执行的第一步。

DBS 不负责：

- 直接重写全文。
- 擅自采用诊断。
- 修改用户文件。

用户选择要采用的诊断后，再由写作引擎生成 V2。

## 安装检查

```bash
python3 tools/validate_pipeline.py
```

若缺少 `dbs-content`：

```bash
npx -y skills add dontbesilent2025/dbskill -g --all
```

## 初稿后的可选视频制作

内容主管线完成后，可继续使用仓库中的视频资产：

```text
确认稿件
  ↓
templates/storyboard.md 生成分镜
  ↓
拍摄人物原声
  ↓
templates/hyperframes-overlay 生成信息动画
  ↓
tools/compose_video.py 合成
  ↓
tools/verify_video.py 验收
```

视频制作是下游生产，不改变 Content OS 的四阶段定义。
