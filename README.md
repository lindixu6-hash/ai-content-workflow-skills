# AI Content Workflow Skills

把一个模糊选题，逐步变成可直接朗读、可审核、可发布的小红书或短视频口播稿。

这不是“一句话生成终稿”的提示词，而是一套保留人工判断点的四阶段工作流：

```text
播种（说清楚想写什么）
  ↓
发芽（生成 5 个跨领域视角）
  ↓
成长（选择视角，生成完整 V1）
  ↓
人工确认
  ↓
修剪（五维审核，只提建议，不擅自改稿）
```

## 30 秒了解

仓库包含两个可独立使用的 Skill：

| Skill | 作用 | 什么时候用 |
|---|---|---|
| `xhs-post-writer` | 播种、发芽、成长、修剪四阶段写作 | 有选题、经历或模糊想法，想写成观点帖或口播稿 |
| `xhs-5d-review` | 从核心逻辑、结构、AI 味、标题 Hook、传播力五个维度审稿 | 已经有初稿，只想获得具体诊断和改句 |

核心边界：

- V1 必须先完整展示，用户确认后才能审核。
- 展示不等于写入，未经同意不修改文件。
- 审核必须给出“完整原句 → 具体诊断 → 完整改句”。
- 用户保留选题、选角度和最终发布三个决定。

## 适合谁

- 想把真实经历写成认知观点内容的人。
- 经常让 AI 改稿，但越改越像 AI 的人。
- 需要明确的人机协作节点，不想让 AI 自动覆盖原稿的人。
- 想复用一套选题、写稿、审核流程的内容创作者。

它不适合批量洗稿、事实未经核验的伪科普，以及完全无人确认的一键发布。

## 3 分钟开始

### 1. 克隆仓库

```bash
git clone https://github.com/lindixu6-hash/ai-content-workflow-skills.git
cd ai-content-workflow-skills
```

### 2. 安装 Skill

在 Trae 项目根目录执行：

```bash
mkdir -p .trae/skills
cp -R skills/xhs-post-writer .trae/skills/
cp -R skills/xhs-5d-review .trae/skills/
```

安装后应看到：

```text
.trae/skills/
├── xhs-post-writer/
│   └── SKILL.md
└── xhs-5d-review/
    └── SKILL.md
```

其他支持 `SKILL.md` 的 Agent 环境也可以使用，但需要把两个目录复制到对应的 Skill 根目录。

### 3. 发起第一次对话

把下面这句话发给 Agent：

```text
开始播种：我想写一个关于“____”的口播稿。
我的真实经历是：____。
我希望观众看完后：____。
```

之后按阶段继续：

```text
开始发芽。
```

Agent 会给出 5 个不同视角。选择其中一至两个：

```text
选择 02 和 04，开始成长。
```

Agent 会完整展示口播稿 V1，并停下来等待确认。确认稿件后再说：

```text
开始 5D Review。
```

## 最短使用示例

```text
用户：开始播种。我发现自己总在收藏教程，却很少真正开始。

Agent：澄清经历、受众和表达目标，不直接写终稿。

用户：开始发芽。

Agent：给出 5 个机制不同、可核验的跨领域视角。

用户：选择 01 和 03，开始成长。

Agent：输出完整 V1，然后停止。

用户：开始 5D Review。

Agent：输出 5 张审核表，给出原句、诊断和可直接替换的改句。

用户：采用表 1 的 A 版和表 3 的建议，生成 V2。
```

## 只有初稿，直接审稿

不必从播种开始。把稿件贴进对话或提供文件路径：

```text
请用 xhs-5d-review 审核这篇稿件。
只输出五张审核表，不要直接覆盖原稿。
```

审核固定包含：

1. 核心逻辑。
2. 结构逻辑。
3. AI 味。
4. 标题 Hook。
5. 共鸣传播。

## 四阶段分别产出什么

| 阶段 | 输入 | 输出 | 人工检查点 |
|---|---|---|---|
| 播种 | 主题、经历、情绪、受众 | 清晰的核心命题 | 用户确认真正想表达什么 |
| 发芽 | 已确认的命题 | 5 个跨领域视角与 Aha | 用户选择最有感觉的角度 |
| 成长 | 选中的视角 | 可直接朗读的完整 V1 | 用户先阅读、修改或确认 |
| 修剪 | 用户确认的 V1 | 5 张诊断表和具体改句 | 用户决定采用哪些建议 |

如果发芽阶段使用外部事实，Agent 应检索并保留来源。当前环境不能检索时，必须说明限制，不能编造。

## 定制你的账号风格

公开版不预设创作者的公司、学校、职业、城市、年龄或价值立场。

第一次使用时，可以主动提供：

```text
我的账号定位：
目标受众：
常用语气：
不希望出现的表达：
可以公开的经历：
必须保留的观点：
```

建议把私人身份配置保存在自己的私有项目中，不要提交到公开仓库。Skill 在信息不足时应先询问，不应自行猜测。

## 教程和产品类内容

当内容用于介绍产品、Workflow、Skill 或教程时，`xhs-post-writer` 会额外检查销售链路：

```text
目标痛点 → 明确结果 → 真实证据 → 降低门槛 → 可信机制
→ 价值确认后再给免费或开源 → 明确领取动作
```

这条结构用于防止压缩时长时只剩功能介绍，丢掉观众为什么要继续看的理由。

## 常见问题

### Skill 没有自动触发

确认目录位于当前项目的 `.trae/skills/`，并重新开始一轮对话。也可以明确说：

```text
请使用 xhs-post-writer，开始播种。
```

### 发芽内容很空泛

要求 Agent 给出可核验的人物、年份、事件或数据，并检查它找到的是相同因果机制，而不是相同关键词。

### Agent 直接审核 V1

提醒它遵守阶段边界：

```text
成长阶段只展示完整 V1。等我确认后才能开始修剪。
```

### 审核只有方向，没有改句

明确要求：

```text
每个问题都必须给出完整原句、具体诊断、改句 A 和改句 B。
```

### 我只想写稿，不做视频

只安装并使用两个 Skill 即可。`workflow/`、`templates/` 和 `tools/` 都是可选资源。
